# Google OAuth — Design & Decisions

**Status:** design approved 2026-05-18 (brainstorm spanning 2026-05-15 → 2026-05-18). All four sections locked. Next step: hand off to `writing-plans` skill to produce `docs/google/2026-05-18-plan.md`.

**Build target:** version 4 in `app-sdk/build-version.json` (after VK=2, Yandex=3).

---

## Goal

Add Google as a third OAuth provider to `/app-sdk` and `/server`, matching the existing VK + Yandex SDK pattern. Test app: Android build only; iOS code written but uncompiled (matches existing project convention).

UX: tapping "Sign in with Google" surfaces the system-level account chooser bottom-sheet rendered by Google Play services on Android, and the Google-hosted ASWebAuthenticationSession-equivalent flow on iOS. No app-switching to Gmail/YouTube — the same Play-services component that powers those apps surfaces directly inside ours.

---

## Approach: custom Expo native module + Credential Manager (Android) / GoogleSignIn pod (iOS)

**Decision (2026-05-15 brainstorm):** hand-roll a custom Expo native module under `app-sdk/modules/expo-google-sdk/`, parallel to `expo-vk-sdk` and `expo-yandex-sdk`. Do **NOT** use `@react-native-google-signin/google-signin` (community library) or `expo-auth-session`.

**Why:**
- **Consistency.** Three providers, one shape (`app-sdk/plugins/withXxxSDK.js` + `app-sdk/modules/expo-xxx-sdk/`).
- **Future-proof on Android.** Credential Manager is Google's current recommendation; the classic `com.google.android.gms:play-services-auth` / `GoogleSignInClient` SDK is **deprecated** and being removed. The free community library still wraps the deprecated path; the Credential-Manager-based variant is paid.
- **Free.** No license cost.
- **Small.** ~150 lines of Kotlin + ~70 lines of Swift, comparable to the existing Yandex module.
- **Google's flow is simpler than Yandex's** — ID token comes back in the credential directly, no separate `getJwt()` round trip.

**Reference patterns in repo (read but DO NOT blindly copy, especially iOS — VK/Yandex iOS code is hardened but never compiled and may contain latent bugs):**
- [app-sdk/plugins/withYandexSDK.js](../../app-sdk/plugins/withYandexSDK.js)
- [app-sdk/modules/expo-yandex-sdk/android/src/main/java/expo/modules/yandexsdk/ExpoYandexSDKModule.kt](../../app-sdk/modules/expo-yandex-sdk/android/src/main/java/expo/modules/yandexsdk/ExpoYandexSDKModule.kt)

## Section 1 — Architecture (approved)

**Android stack (`app-sdk/modules/expo-google-sdk/android/`):**

Gradle dependencies (versions verified 2026-05-15 against [Google's Credential Manager docs](https://developer.android.com/identity/sign-in/credential-manager-siwg-implementation)):

```kotlin
dependencies {
    implementation("androidx.credentials:credentials:1.7.0-alpha02")
    implementation("androidx.credentials:credentials-play-services-auth:1.7.0-alpha02")
    implementation("com.google.android.libraries.identity.googleid:googleid:<latest>")
}
```

Module: `CredentialManager.create(activity).getCredential(...)` (suspend, coroutine-based — NOT raw Thread like the Yandex module). Returns a `GoogleIdTokenCredential` with `.idToken` (RS256 JWT string).

**Critical:** use `GetSignInWithGoogleOption(WEB_CLIENT_ID, nonce)` for our explicit-button flow — **not** `GetGoogleIdOption` with two-tier filtered/unfiltered fallback. `GetGoogleIdOption` is for the bottom-sheet auto-prompt UX shown on app launch; `GetSignInWithGoogleOption` is the button-flow primitive and matches our intent.

**iOS stack (`app-sdk/modules/expo-google-sdk/ios/`):**

Podfile: `pod 'GoogleSignIn'` (v9.0.0+ for nonce parameter support). Min iOS version per Google: iOS 13+.

Info.plist keys (set by config plugin):
- `GIDClientID` = iOS Client ID
- `GIDServerClientID` = Web Client ID (so `aud` claim matches what backend validates)
- `CFBundleURLTypes` entry with reversed iOS Client ID as URL scheme

App delegate: `GIDSignIn.sharedInstance.handle(url)` in `application(_:open:options:)` (or SwiftUI `.onOpenURL`).

Sign-in call: `GIDSignIn.sharedInstance.signIn(withPresenting: rootVC, hint: nil, additionalScopes: nil, nonce: nonce) { result, error in ... }` → `result.user.idToken?.tokenString`.

**Expo config plugin (`app-sdk/plugins/withGoogleSDK.js`):**

Same shape as [withYandexSDK.js](../../app-sdk/plugins/withYandexSDK.js).
- Android: manifest placeholder `GOOGLE_WEB_CLIENT_ID` injected into `defaultConfig`; Kotlin module reads via merged manifest meta-data.
- iOS: writes `GIDClientID` + `GIDServerClientID` + reversed-iOS-ID URL scheme.

**JS layer:** `app-sdk/src/hooks/useGoogleAuth.ts` parallel to `useYandexAuth.ts`. Generates nonce, calls module, posts to backend, stores session JWT via `SecureStore`.

**Backend (`server/`):**
- `server/src/services/google.js` — new. Uses `google-auth-library`. `new OAuth2Client().verifyIdToken({ idToken, audience: WEB_CLIENT_ID })` then `ticket.getPayload()`. The library auto-caches Google's JWKs based on `Cache-Control`; no manual cache logic needed.
- `server/src/routes/auth.js` — add `POST /auth/google/exchange-jwt`.
- `server/.env` — add `GOOGLE_WEB_CLIENT_ID`. No Google secret stored (unlike Yandex HS256).
- User upsert: existing `{provider: 'google', providerId: <sub>}` generic schema works unchanged.

**Mobile module return contract** (pick once, don't change):
```ts
type GoogleAuthSuccess   = { idToken: string };
type GoogleAuthCancelled = { cancelled: true };
type GoogleAuthResult    = GoogleAuthSuccess | GoogleAuthCancelled;
// Or thrown rejection on hard errors.
```

## Section 2 — Data flow (approved)

```
[User taps Google button in app]
   │
   ▼
[useGoogleAuth.signIn() — JS]
   │ generate random nonce (32-byte base64 url-safe)
   ▼
[ExpoGoogleSDK.authorize({ nonce }) — native]
   │
   ├─ Android (Kotlin, coroutine):
   │     CredentialManager.create(activity).getCredential(
   │       GetCredentialRequest(GetSignInWithGoogleOption(WEB_CLIENT_ID, nonce))
   │     )
   │     → result.credential as CustomCredential
   │     → GoogleIdTokenCredential.createFrom(credential.data).idToken
   │
   └─ iOS (Swift):
         GIDSignIn.sharedInstance.signIn(
           withPresenting: rootVC, hint: nil, additionalScopes: nil, nonce: nonce
         ) { result, error in ... }
         → result.user.idToken?.tokenString
         (GIDServerClientID set in Info.plist → ID token aud = Web Client ID)
   │
   ▼
[returns { idToken } | { cancelled: true } | rejects]
   │
   ▼
[JS: POST /auth/google/exchange-jwt  body: { idToken, nonce }]
   │
   ▼
[server/src/routes/auth.js → server/src/services/google.js]
   │  new OAuth2Client().verifyIdToken({ idToken, audience: WEB_CLIENT_ID })
   │  → ticket.getPayload()  (sig, iss, aud, exp validated by library)
   │  → assert payload.nonce === requestBody.nonce
   │  → assert payload.email_verified === true
   │  → upsert user { provider: 'google', providerId: payload.sub, email, name, picture }
   │  → sign session JWT (HS256 with JWT_SECRET, same as VK/Yandex)
   ▼
[returns { token: <session-jwt>, user: {...} }]
   │
   ▼
[JS stores session JWT in SecureStore — same as Yandex/VK]
```

**Nonce binding (approved):** included from initial implementation. JS generates a 32-byte base64 random string, passes to native module as a parameter, and includes it verbatim in the backend POST. Google embeds it as `nonce` claim in the ID token. Backend compares directly (no hashing). Defends against replay if a token is intercepted.

## Section 3 — Error handling (approved)

**Android (Kotlin module):**

| Caught exception | Mapped result |
|---|---|
| `GetCredentialCancellationException` | resolve `{ cancelled: true }` — cancellation is a normal outcome, **not** a rejection |
| `NoCredentialException` | reject `NO_GOOGLE_ACCOUNT` — actionable; no Google account configured on device |
| `GoogleIdTokenParsingException` | reject `INVALID_TOKEN` |
| Other `GetCredentialException` | reject `GOOGLE_AUTH_ERROR` |
| `currentActivity !is ComponentActivity` | reject `NO_ACTIVITY` |

**iOS (Swift module):**

| Condition | Mapped result |
|---|---|
| `error.domain == kGIDSignInErrorDomain && error.code == -5` (`.canceled`) | resolve `{ cancelled: true }` |
| Other error | reject `GOOGLE_AUTH_ERROR` with localizedDescription |
| `result.user.idToken == nil` (defensive — shouldn't happen with GIDServerClientID set) | reject `NO_ID_TOKEN` |

Note: the `-5` cancellation code is the documented value from `GIDSignInError.Code`. The Yandex iOS module used a placeholder `-2` value flagged as unverified — do not repeat that pattern.

**JS layer (`useGoogleAuth.ts`):** cancellation returns silently (no error UI); other rejections are surfaced. Network/HTTP errors from the backend POST are surfaced via the hook's `error` state.

**Server (`POST /auth/google/exchange-jwt`):**

| Failure | Response |
|---|---|
| Missing `idToken` or `nonce` | `400 INVALID_REQUEST` |
| `verifyIdToken` throws (bad signature / wrong aud / expired) | `401 INVALID_TOKEN` |
| `payload.nonce !== body.nonce` | `401 NONCE_MISMATCH` |
| `payload.email_verified !== true` | `403 EMAIL_NOT_VERIFIED` |
| User upsert / DB failure | `500 SERVER_ERROR` |

## Section 4 — Testing strategy (approved)

**Mirrors the existing Yandex test pattern** ([server/tests/services/yandex.test.js](../../server/tests/services/yandex.test.js), [server/tests/routes/auth.yandex-jwt.test.js](../../server/tests/routes/auth.yandex-jwt.test.js)).

### Backend — service unit tests

New file: `server/tests/services/google.test.js`.

**Approach: mock `OAuth2Client.verifyIdToken`** to return a chosen payload, then test our wrapper logic. (Considered and rejected: hand-rolled RS256 keypair + JWKs monkey-patch — adds `jose` dep and ~30 lines of scaffolding to exercise signature paths that belong to the library, not us. Yandex's HS256 alg-confusion test exists because that attack is our wrapper's responsibility; the Google equivalents are all caught inside `google-auth-library`.)

Tests (~5):
1. Resolves with `{sub, email, name, picture, providerId}` shape on valid payload.
2. Throws `google_nonce_mismatch` when `payload.nonce !== expectedNonce`.
3. Throws `google_email_not_verified` when `payload.email_verified !== true`.
4. Calls `verifyIdToken` with `audience: WEB_CLIENT_ID` (assertion on mock call args).
5. Re-throws library errors as `google_id_token_invalid` (uniform error-code surface for the route layer).

### Backend — route integration tests

New file: `server/tests/routes/auth.google-jwt.test.js`. Same shape as the Yandex route test: `jest.mock('../../src/services/google')`, `supertest`, temp users file, console silenced in `beforeAll`.

Tests:
1. `400 missing_fields` when `idToken` or `nonce` is absent.
2. `500 server_misconfigured` when `GOOGLE_WEB_CLIENT_ID` is not set.
3. `401 google_id_token_invalid` when service throws verification error.
4. `401 google_nonce_mismatch` when service throws nonce error.
5. `403 google_email_not_verified` when service throws email-verified error.
6. `200` + app JWT signed with `JWT_SECRET` + user persisted with `provider: 'google'`, `providerId: <sub>`.
7. No duplicate on repeat sign-in with same `sub`.

### Mobile — no automated tests

Matches VK + Yandex convention in this repo (neither has them).
- Android: build release APK locally, install on physical device, run manual checklist below.
- iOS: code written, never compiled in test app (no Apple Team ID). Production app build is where iOS gets verified end-to-end.

### Manual test checklist (Android release APK on physical device)

| # | Scenario | Expected |
|---|----------|----------|
| 1 | Tap Google button, pick account, consent | App receives session JWT, user appears logged-in |
| 2 | Tap button, dismiss picker (back/outside-tap) | No error UI; button returns to idle silently |
| 3 | Tap button with no Google account on device | Error UI: "No Google account on this device" |
| 4 | Sign in with airplane mode on (after picker) | Error UI: network error; picker did not crash |
| 5 | Tamper with nonce in JS before POST (`__DEV__` flag) | Server `401 google_nonce_mismatch`; app shows generic auth error |
| 6 | Sign out (calls `clearCredentialState`), sign in again | Account picker re-appears (no silent re-auth) |
| 7 | Sign in twice with same account | Second sign-in works without re-consent; no duplicate user in `users.json` |
| 8 | Sign in with a different Google account on device | Picker shows both; selecting other creates/finds a different user record |

Test #5 needs a `__DEV__`-gated escape hatch in the JS layer (small, ~3 lines).
